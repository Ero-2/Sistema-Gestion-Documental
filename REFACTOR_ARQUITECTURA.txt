────────────────────────────────────────────────────────────────────────────────
 QUÉ PEDÍA LA SPEC
────────────────────────────────────────────────────────────────────────────────
- 3 grupos desacoplados.
- Comunicación UNIDIRECCIONAL por APIs REST.
- Sin polling / cron / long-polling / intervalos (para sync documental).
- Auth centralizada en .NET (única fuente de usuarios/roles/passwords).
- Seeders (datos de prueba precargados).
- UI sin IDs hasheados / encriptados.

────────────────────────────────────────────────────────────────────────────────
 QUÉ ENCONTRÉ ROTO vs SPEC
────────────────────────────────────────────────────────────────────────────────
| Problema                                                  | Violaba                          |
|-----------------------------------------------------------|----------------------------------|
| FastAPI tenía poller leyendo SQL cada 30s (_auto_sync_loop)| "sin polling"                   |
| FastAPI + PHP conectaban directo a SQL Server             | "solo unidireccional, no DB ajena"|
| Webhook /indexer/notify hacía .NET->FastAPI->SELECT a SQL | "FastAPI no toca SQL"            |
| No había seeders                                          | "datos de prueba precargados"    |

────────────────────────────────────────────────────────────────────────────────
 CÓMO FUNCIONA AHORA
────────────────────────────────────────────────────────────────────────────────

LOGIN (auth centralizada):
   Usuario en PHP/FastAPI -> ingresa credenciales
     -> sistema secundario llama .NET POST /api/v1/auth/validate
     -> .NET valida contra SQL Server (único con usuarios)
     -> responde {userId, userName, roles}
     -> PHP crea sesión / FastAPI emite su JWT
   Secundarios NO guardan passwords.

APROBACIÓN DE DOCUMENTO (eventos, inmediato):
   .NET aprueba doc (estado -> Approved en SQL Server)
     -> push HTTP paralelo, inmediato:
        |-> POST php/api/events.php?action=approve  -> inserta en PostgreSQL
        |-> POST fastapi/indexer/upsert            -> lee PDF del volumen,
                                                       extrae texto, indexa Mongo
   Sin polling. Sin que PHP/FastAPI toquen SQL. Error en uno no bloquea el otro.

BÚSQUEDA PÚBLICA:
   Usuario busca en PHP -> PHP llama fastapi/indexer/search?q=...
     -> Mongo full-text -> devuelve postgres_ids
     -> PHP consulta PostgreSQL local -> muestra resultados

ARCHIVOS:
   Todos los servicios comparten volumen Docker uploads_data
   (permitido — es un volumen de archivos, no una base de datos).
